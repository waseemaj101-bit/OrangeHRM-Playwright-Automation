# OrangeHRM Playwright Framework (UI + API)

Playwright + TypeScript framework using the Page Object Model (POM) for the
OrangeHRM demo site: https://opensource-demo.orangehrmlive.com

## Setup

```bash
npm install
npx playwright install chromium
cp .env.example .env      # optional, defaults already point to the demo site
```

## Run

```bash
npm test                  # UI + API
npm run test:ui           # UI only
npm run test:api          # API only
npm run test:smoke        # only @smoke tests
npm run test:pim          # one module, UI + API (also: admin, leave, recruitment)
npm run test:headed       # watch the browser
npm run report            # open the HTML report
npm run typecheck         # TypeScript check
```

## Structure

```
config/        env.config.ts (URL, credentials, timeouts), routes.ts (page URLs)
data/          static test data per module (JSON)
utils/         dataFactory.ts (dynamic data via faker), helpers.ts (dates, regex)
pages/         Page objects: BasePage + Login, Dashboard, PIM, Admin, Leave,
               Recruitment, MyInfo; components/ = SideMenu, Toast, DataTable
api/           API clients: BaseApi + Employee, Admin, Recruitment, Leave
fixtures/      test.fixture.ts: page objects, API clients, employee/candidate data
tests/
  auth.setup.ts      logs in once and saves the session
  ui/                login, dashboard, pim, admin, leave, recruitment, myinfo specs
  api/               auth, pim, admin, leave, recruitment *.api.spec.ts
```

## How it stays stable

- **English always:** `playwright.config.ts` (`use` section) sets `locale: 'en-US'` and an
  `Accept-Language: en-US` header on every request. OrangeHRM also keeps a language
  setting in the app (Admin > Configuration > Localization). If a UI run ever shows
  another language, check that setting first.
- **Locators:** `getByRole`, `getByText`, `getByPlaceholder` and `getByAltText` first.
  OrangeHRM has almost no stable `id` attributes, so `testIdAttribute` is set to `id`
  (`page.getByTestId('x')` matches `id="x"`) for any you add later. The few CSS fallbacks
  (loader, form group, dropdown, row icons) are isolated in `BasePage` and `DataTable`.
- **No fixed waits:** only web-first assertions and waits on the real search API calls.
- **Unique data:** every record is generated by `dataFactory.ts`, so runs never collide.
- **Fast, independent setup:** the `employee` and `candidate` fixtures are created through
  the API and deleted through the API afterwards, even if the test fails.
- **Session reuse:** one login for all specs except `login.spec.ts`. API tests use the same session.
- **Year-end safe:** leave tests pick a working day inside the current year.
- **Retries:** 1 locally, 2 on CI, to absorb rare hiccups on the shared demo.

## Notes

- The demo is shared and resets regularly. Do not enter real personal data.
- API paths and payloads follow OrangeHRM 5.x (`/web/index.php/api/v2/...`). If the vendor
  changes them, update only the files in `api/`.
